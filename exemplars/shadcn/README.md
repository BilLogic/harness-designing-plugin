# shadcn/ui — harness exemplar

Self-contained Storybook demonstrating what the harness-designing plug-in's `/hd:design-system establish` command produces when run against a shadcn/ui project.

## Run

```bash
cd exemplars/shadcn
npm install
npm run storybook
```

Storybook opens at `http://localhost:6006`. Sidebar order:

```
0-welcome/
1-foundations/   Principles, Tokens
2-styles/        Color, Typography, Spacing
4-components/    Button, Input, Card
```

## What's here

| Path | What |
|---|---|
| `src/styles/tokens.css` | Canonical shadcn tokens (OKLCH primitives + semantic role pairs + spacing/type scales) |
| `src/components/{Button,Input,Card}.tsx` | Local stubs visually approximating the canonical shadcn components — no `npm install @shadcn/ui` required |
| `src/components/*.stories.tsx` | Minimal stories powering `<Canvas of={...} />` blocks in the .mdx pages |
| `docs/0-welcome/README.mdx` | Entry page — what to look at and why |
| `docs/1-foundations/{principles,tokens}.mdx` | The WHY — design commitments + token tier model |
| `docs/2-styles/{color,typography,spacing}.mdx` | The WHAT — visual values rendered live from `tokens.css` |
| `docs/4-components/{button,input,card}.mdx` | Per-component pages with `<Panel>` blocks for variants/states |
| `.storybook/main.ts` | Framework: `@storybook/react-vite`, stories glob covers `docs/**/*.mdx` + `src/**/*.stories.*` |
| `.storybook/preview.ts` | Single light/dark theme global (shadcn convention); `.dark` class applied via decorator |
| `.storybook/harness-blocks/*.tsx` | The 15 custom MDX blocks the harness ships (Panel, Swatch primitives, etc.) — copied verbatim from `skills/hd-design-system/assets/harness-blocks/` |

## What this exemplar proves

- Single `.mdx` per topic serves both an agent (markdown body) and humans (rendered Storybook page) with zero duplication.
- Numbered sidebar prefixes (`1-foundations/`, `2-styles/`, `4-components/`) cleanly drive Storybook's IA from filesystem layout.
- Component pages compose `<Panel>` + `<Canvas>` for variant matrices — the `<Panel>` shows source path, `<Canvas>` shows live output.
- All three exemplars (shadcn + Material + Fluent) ship the SAME `.tsx` harness-blocks because Storybook docs renders in React regardless of the story framework.

## What's intentionally minimal in v1

- No auto-generated `Tracker.mdx` or `Audit.mdx` (those are runtime-generated by `scripts/generate-tracker.mjs` + `scripts/generate-audit.mjs` against a real repo's index-manifest)
- No `5-patterns/` or `7-specs/` folders (optional Q6/Q8 enablement, skipped in v1)
- Only 3 components — Button, Input, Card universally exercise variants/composition/states
