## Decisions

- **Pair, don't pick.** Every fill has a foreground sibling. If text needs to sit on `--primary`, use `--primary-foreground`; never `--foreground`.
- **OKLCH** for predictable contrast. Hex equivalents are in `tokens.css` comments; the canonical values are OKLCH.
- **Dark mode = remap, not invert.** `.dark` reassigns the same role names to different OKLCH values. No component code changes between themes.
- **No tier-3 tokens.** No `--button-background-hover` or `--card-border-active`. Components consume tier-2 directly; if you need a new pair, add it.

## Accessible contrast across themes

The pairs ship pre-checked for WCAG AA. Below: actual ratios in light and dark.

| Pair | Light | Dark |
|---|---|---|
| `--foreground` on `--background` | 19.5:1 | 18.7:1 |
| `--primary-foreground` on `--primary` | 18.4:1 | 18.7:1 |
| `--muted-foreground` on `--background` | 4.83:1 | 4.61:1 |
| `--destructive-foreground` on `--destructive` | 6.21:1 | 5.95:1 |
| `--card-foreground` on `--card` | 19.5:1 | 17.4:1 |

## Do's and don'ts

| Do | Don't |
|---|---|
| Use the role pair (`--card` + `--card-foreground`) | Mix tiers (`--background` text on `--card` surface) |
| Toggle `.dark` on `<html>` to switch themes | Use `prefers-color-scheme` directly in components |
| Add new pairs to `tokens.css` when a role is genuinely new | Override `--primary` for "this one button" |
| Inherit color via `currentColor` for icons | Hardcode color on icons inside Buttons |
| Use `--muted-foreground` for low-emphasis text | Use `--foreground` at 60% opacity to fake it |

## Agent prompt guide

> If the surface is a card → use `--card` + `--card-foreground`. If a button → match the role to intent (primary / secondary / destructive / outline), and pair it with the matching `-foreground`. Never sample a hex value from a Figma file — find the role, use the var. Never reach for tier-3 tokens — they don't exist.
