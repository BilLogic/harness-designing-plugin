# Elevation

> shadcn doesn't expose an elevation token scale. Depth is conveyed by **surface tier**, not by **shadow depth**. Three named surfaces, three implicit shadows, no z-index ladder to memorize.

## Tier reference

| Tier | Token | Shadow | Use |
|---|---|---|---|
| **Base** | `--background` | (none) | Page surface, app shell |
| **Raised** | `--card` | `0 1px 2px 0 rgb(0 0 0 / 0.05)` | Cards, panels, sidebars, list items |
| **Floating** | `--popover` | `0 4px 12px -2px rgb(0 0 0 / 0.12)` + lift | Tooltips, menus, dialogs, popovers |

Components that live on a tier own that tier's shadow internally — `Card.tsx` ships with the raised shadow inline. You don't apply elevation manually; you pick the surface tier.

## Why no shadow scale?

A 0–5 elevation scale is common but creates a long tail of "is this a 2 or a 3?" decisions. Three tiers fits the actual product surface — every UI element is either a page background, a discrete content surface, or floating above content.

## Decisions

- **No `--shadow-*` tokens.** A scale of 0–5 elevations creates ambiguity. Three tiers fits the actual product surface.
- **Shadow lives in the component, not the token.** `Card.tsx` ships `boxShadow` inline. If three components ever need the *same* shadow that isn't a tier, only then promote to a token.
- **Tier name = shadow.** "Floating" implies the popover shadow. You never specify both.

## Dark theme

Shadows fade in dark mode — they read as luminance, and dark surfaces have less luminance to give up. shadcn handles this implicitly: borders carry more weight in `.dark`, shadows carry less. No per-tier dark-shadow override needed.

## When you genuinely need a shadow outside the tier system

A floating action button that hovers above a card might want a stronger shadow than the popover tier. Declare it inline:

```tsx
<button style={{ boxShadow: '0 8px 24px -8px rgb(0 0 0 / 0.25)' }} />
```

Don't add to `tokens.css` unless three or more components need the same value.

## Do's and don'ts

| Do | Don't |
|---|---|
| Pick the tier (`--background` / `--card` / `--popover`) | Compose your own shadow scale (`--shadow-sm`, etc.) |
| Trust the component to ship its tier's shadow | Reach for `boxShadow` inline on `Card` |
| Use `--popover` for any element that floats above content | Use a higher z-index without changing the tier |
| Leave dark-theme shadows lighter than light-theme | Force the same shadow opacity in both themes |
| Stack tier-by-tier (page → card → popover) | Skip a tier (page → popover with no card between) |

## Agent prompt guide

> When picking a surface depth: use `--background` for the page, `--card` for any discrete content surface, `--popover` for anything that floats. Never invent shadow tokens. If a design calls for "elevation 3", ask which tier the surface conceptually belongs to — pick that tier instead.
