# Typography

> shadcn/ui doesn't ship a custom type system — it inherits the [Tailwind v4 default scale](https://tailwindcss.com/docs/font-size). The 8 sizes below cover the entire surface; values render live from `src/styles/tokens.css`.

## Scale → use mapping

| Token | Use | Semantic |
|---|---|---|
| `text-4xl` | Display 1 — hero pages, marketing surfaces | `<h1>` rare |
| `text-3xl` | Display 2 — page titles | `<h1>` |
| `text-2xl` | Heading 1 — section heading | `<h2>` |
| `text-xl` | Heading 2 — sub-section heading | `<h3>` |
| `text-lg` | Heading 3 — card title, form section | `<h3>` / `<h4>` |
| **`text-base`** | **Default body** — paragraphs, descriptions | `<p>` |
| `text-sm` | Body small — labels, dense UI, list items | `<p>` / `<span>` |
| `text-xs` | Caption — metadata, hints, badges | `<span>` |

## Font families

| Token | Stack |
|---|---|
| `--font-sans` | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` |
| `--font-mono` | `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace` |

Override `--font-sans` **once at the root** when introducing a branded face — every component picks it up automatically.

## Weights

Four weights cover the surface. The system fonts ship with these out of the box; custom faces should provide the same set.

| Weight | Used for |
|---|---|
| `400` (regular) | Body, descriptions |
| `500` (medium) | Buttons, labels, table headers |
| `600` (semibold) | Card titles, section headings |
| `700` (bold) | Page titles, display |

## Line height

Per-size defaults from Tailwind:

| Size | Line height |
|---|---|
| `text-xs` to `text-base` | `1.5` (body) |
| `text-lg` to `text-xl` | `1.4` (subheading) |
| `text-2xl` to `text-3xl` | `1.25` (heading) |
| `text-4xl` | `1.1` (display) |

Override per-component when needed; don't tokenize variants we don't actually use.

## Truncation patterns

When content overflows its container, use one of three patterns. Pick by intent.

## Decisions

- **No custom font face by default.** System UI fonts ship instantly with zero load weight. If a brand demands a custom face, set `--font-sans` to the imported family — every component picks it up.
- **No type "scale" beyond Tailwind defaults.** A 13-step scale invites bikeshedding. The 8 sizes above cover 95% of real usage.
- **Line-height defaults to Tailwind's per-size** (1.5 for body, 1.25 for headings, 1 for display). Override per-component if needed; don't tokenize variants we don't use.
- **Tabular numerals** for numeric values that align in columns (`fontVariantNumeric: 'tabular-nums'`). Mix into stat tiles, table cells, dial readouts.

## Do's and don'ts

| Do | Don't |
|---|---|
| Use `text-base` for body, `text-sm` for labels | Add a `text-md` "between" — pick `base` or `sm` |
| Override `--font-sans` once at the root for branded faces | Apply `font-family` per-component |
| Pair heading sizes with semantic `<h1>`/`<h2>`/etc. | Use type size to convey hierarchy without semantics |
| Use `tabular-nums` for numeric columns | Hand-pad numbers with spaces to align |
| Truncate single-line with `text-overflow: ellipsis` | Truncate multi-line with `text-overflow: ellipsis` (won't work) |

## Agent prompt guide

> Body copy → `text-sm` for compact UI, `text-base` for readable prose. Page title → `text-3xl` or `text-4xl`. Section heading → `text-2xl`. Card title → `text-lg`. Labels and metadata → `text-xs`. Use the semantic HTML tag (`<h1>`–`<h6>`) appropriate to document outline; don't pick by visual size alone. Numeric columns → add `font-variant-numeric: tabular-nums`.
