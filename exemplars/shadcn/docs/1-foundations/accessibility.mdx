# Accessibility

> Every component meets WCAG 2.1 AA. Color contrast, keyboard navigability, focus visibility, screen-reader semantics — non-negotiable, encoded as per-component contracts. Each component story documents the contract for that component; this page documents the system-wide rules.

## The four baseline commitments

### 2 · Keyboard navigation — every interactive surface reachable

Tab visits in DOM order. Esc closes overlays. Arrow keys traverse composite widgets (tabs, accordion, slider). The harness ships these for free; you don't add them, you don't remove them.

| Component | Keyboard contract |
|---|---|
| `Button` | Enter / Space activates · Tab focuses |
| `Input` / `Textarea` | Tab focuses · standard text-edit keys |
| `Checkbox` / `Switch` | Space toggles · Tab focuses |
| `Tabs` | Arrow Left/Right changes tab · Home / End jumps |
| `Accordion` | Tab visits triggers · Enter / Space toggles |
| `Dialog` | Esc closes · focus moves to first focusable on open |
| `Slider` | Arrow keys step · Home / End to bounds |

The ring uses `:focus-visible`, not `:focus` — keyboard users see it, mouse users don't. The 2px outline + 2px outline-offset clears any element padding so the ring is never clipped.

### 4 · Screen-reader names — every control has one

A name is what assistive tech announces. It comes from one of: visible text, `<label>`, `aria-label`, or `aria-labelledby`. Placeholder text is **not** a name.

## Per-component contracts

| Component | Required attrs | Reference |
|---|---|---|
| `Button` (icon-only) | `aria-label="<verb>"` | [Button — Size story](?path=/docs/4-components-button--docs) |
| `Input` (always) | paired `<Label htmlFor>` | [Label — WithInput story](?path=/docs/4-components-label--docs) |
| `Input` (invalid) | `aria-invalid="true"` + `aria-describedby` | [Input — Invalid story](?path=/docs/4-components-input--docs) |
| `Checkbox` (mixed) | `checked="indeterminate"` → `aria-checked="mixed"` | [Checkbox — States story](?path=/docs/4-components-checkbox--docs) |
| `Switch` | native `role="switch"` (announces "on/off") | [Switch — States story](?path=/docs/4-components-switch--docs) |
| `Card` w/ actions | Focus order: header → body → footer | [Card — Default story](?path=/docs/4-components-card-card--docs) |
| `Dialog` | `aria-modal` + focus trap + Esc close | [Dialog — Form story](?path=/docs/4-components-dialog-dialog--docs) |

## Error announcement pattern

A failed validation must surface to AT — quietly hiding errors is a leak.

export const ErrorPattern = () => (
  <div style={{ display: 'flex', flexDirection: 'column', gap: '0.5rem', maxWidth: 360 }}>
    <Label htmlFor="acc-err">Email</Label>
    <Input
      id="acc-err"
      type="email"
      defaultValue="not-an-email"
      aria-invalid="true"
      aria-describedby="acc-err-msg"
    />
    <Alert variant="destructive" style={{ marginTop: '0.25rem' }}>
      <AlertDescription id="acc-err-msg">Enter a valid email address.</AlertDescription>
    </Alert>
  </div>
);

<ErrorPattern />

`aria-invalid="true"` on the input + `aria-describedby` linking to the error text. Screen readers announce the error after the field name when focus lands.

## Focus order in compound components

`Card` → `CardHeader` → `CardContent` → `CardFooter` → button order matches DOM order. Don't `tabIndex={-1}` interactive children unless the parent surface itself is the tab stop (e.g., a clickable card).

## Do's and don'ts

| Do | Don't |
|---|---|
| Use `:focus-visible` so the ring shows for keyboard but not mouse | Use `:focus` — punishes mouse users with unwanted rings |
| Pair every form control with `<Label htmlFor>` | Rely on `placeholder` as the accessible name |
| Set `aria-label` on every icon-only button | Ship icon-only controls without a name |
| Test with the a11y addon's contrast checker per-theme | Eyeball contrast — it lies, especially in dark mode |
| Use semantic HTML (`<button>`, `<fieldset>`) | Reach for `<div role="button">` |
| Announce errors via `aria-describedby` | Silently style the field red |

## Agent prompt guide

> When generating new component code: every interactive element gets a name (label, aria-label, or visible text). Every form field pairs with `<Label htmlFor>`. Every disabled state mirrors `aria-disabled`. Focus styles come from `var(--ring)` — never hardcode a focus color. If the contract isn't obvious, surface the gap rather than ship without it.
