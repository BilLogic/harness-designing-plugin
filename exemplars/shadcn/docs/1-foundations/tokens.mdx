# Tokens

> All design decisions live in `src/styles/tokens.css` as CSS custom properties on `:root` and `.dark`. Two tiers — primitives (raw OKLCH values) feed semantic roles (paired by purpose). No third tier; component-level tokens are out of scope on purpose.

## Tier 1 — Primitives

Raw color values in OKLCH. **Never consumed directly by components.** They exist only to feed semantic roles below.

```css
/* in :root */
--background:           oklch(1 0 0);
--foreground:           oklch(0.145 0 0);
--primary:              oklch(0.205 0 0);
--primary-foreground:   oklch(0.985 0 0);
--secondary:            oklch(0.97 0 0);
--secondary-foreground: oklch(0.205 0 0);
--muted:                oklch(0.97 0 0);
--muted-foreground:     oklch(0.556 0 0);
--accent:               oklch(0.97 0 0);
--accent-foreground:    oklch(0.205 0 0);
--destructive:          oklch(0.577 0.245 27.325);
--destructive-foreground: oklch(0.985 0 0);
--border:               oklch(0.922 0 0);
--input:                oklch(0.922 0 0);
--ring:                 oklch(0.708 0 0);
--radius:               0.625rem;
```

## Decisions

- **OKLCH not HSL.** As of shadcn's 2024 update, all default tokens are OKLCH for predictable luminance contrast across themes.
- **No tier-3 component tokens** like `--button-background`. Components consume tier-2 directly. Adding `--button-*` tokens means forking — at which point you own that decision.
- **`.dark` class strategy** rather than `prefers-color-scheme`. Lets users opt in/out of the system preference and lets tests pin a theme.
- **Pair, don't pick.** Always read a fill with its `-foreground` sibling.

## Agent prompt guide

> To pick a token: identify the role (background / foreground / fill / outline) → use the pair (`--primary` + `--primary-foreground`) → never use just one half. If the role doesn't fit any of the 11 pairs above, the right answer is usually a new pair, not a one-off color. Never reach for tier-3 component-specific tokens — they don't exist by design.
