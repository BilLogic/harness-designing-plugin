# Voice

> The product is a tool. It speaks to a competent operator who has work to finish. The voice is **direct**, **technical**, **second-person**. No marketing register inside the product surface — when copy starts feeling like an ad, the page has the wrong author.

## The four rules

Buttons name the action. `Save`, `Delete`, `Send`, `Open`, `Dismiss`. Never `Click here`, never noun-only labels (`Settings` is a destination — fine; `Preferences` for an action button is wrong — say `Edit preferences`).

### 2 · Second-person, present tense

The product addresses you directly. "**Your** subscription renews on Jan 4" — not "The subscription will renew." Past perfect ("Has been saved") and future tense ("Will be processed") usually mean the prose is dodging an outcome.

| Instead of | Say |
|---|---|
| "The file has been saved" | "Saved" |
| "Your account will be created" | "Create your account" |
| "The user can change settings" | "Change your settings" |
| "Subscription renews soon" | "Renews Jan 4" |

### 3 · Specific over generic

Real numbers, real names, real dates. If the system doesn't know yet, say "Unknown" — don't paper over it with vagueness.

## Action labels — canonical verbs

| Verb | Use | Avoid |
|---|---|---|
| `Save` | Persist a change to the current record | `Submit`, `OK`, `Apply` |
| `Send` | Deliver to a recipient | `Submit` |
| `Delete` | Remove permanently | `Remove`, `Discard` (confusing pair) |
| `Cancel` | Abandon current action, no side effects | `No`, `Close` (when destructive paired) |
| `Confirm` | Affirmative resolution of a dialog | `Yes`, `OK` |
| `Dismiss` | Acknowledge a notification | `Close`, `Got it` |
| `Open` | Reveal more of an item | `View`, `See`, `Show` |
| `Edit` | Modify in place | `Change`, `Update` |
| `Continue` | Advance a multi-step flow | `Next`, `Proceed` |

## Errors — the shape

```
Couldn't <verb the user attempted>. <Plain-language reason if helpful>.
[Action button: Try again | Undo | Edit]
```

**Good:** "Couldn't send. The recipient address looks invalid." — `[Edit]`

**Bad:** "An error occurred while processing your request."

## Empty states — the shape

```
<Singular noun describing what's missing>
<One sentence: what populates this surface>
[Primary CTA — the verb that creates one]
```

## Microcopy — label vs placeholder vs helper

Three slots, three jobs.

export const FieldRolesDemo = () => (
  <div style={{ display: 'flex', flexDirection: 'column', gap: '0.5rem', maxWidth: 360 }}>
    <Label htmlFor="voice-email">Email address</Label>

    </span>
  </div>
);

<FieldRolesDemo />

| Slot | Job | Always present? |
|---|---|---|
| Label | Names the field. Every field needs one. | Yes |
| Placeholder | Sample value. Cleared on type. | Optional |
| Helper | Explains the field. Linked via `aria-describedby`. | When useful |

Never use placeholder text as a label substitute — it disappears the moment the user types, and screen readers may skip it.

## Do's and don'ts

| Do | Don't |
|---|---|
| `Save changes` | `Submit form` |
| `12 unread messages` | `You have several unread messages` |
| `Couldn't save — try again` | `An error occurred` |
| `Your draft is preserved locally` | `Don't worry, your data is safe` |
| `Compose` (empty drafts state) | `No drafts to display` |
| Sentence case for buttons | `Title Case` or `ALL CAPS` |
| Use serial commas | Mix comma styles within a session |

## Agent prompt guide

> When writing copy for any UI surface in this codebase: lead with verbs on actions, address the user as "you", use specific numbers and dates, say what failed and what's next on errors. Sentence case throughout. Avoid marketing register ("seamlessly", "powerful", "robust") — the product is a tool, not a pitch. If a label feels generic, ask whether the verb is missing.
