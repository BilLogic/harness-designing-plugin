# Filled Text Field

> Material 3's filled-style text input. The default text field — use unless your surface specifically calls for outlined style. Persistent label that floats above the value when focused or filled.

## Description

A custom element (`<md-filled-text-field>`) wrapping a native `<input>`. Consumes `--md-sys-color-surface-container-highest` for the container fill, `--md-sys-color-on-surface-variant` for the label, `--md-sys-color-primary` for the focused underline. The container has rounded top corners (`shape-corner-extra-small`) and a flat bottom — the underline is the active-state cue.

| State | Cue |
|---|---|
| Empty + unfocused | Label at full size in the input area |
| Empty + focused | Label shrinks + floats to top, underline thickens to 2px in `--md-sys-color-primary` |
| Filled | Same as empty + focused but persists when blur |
| Disabled | Container at 4% surface tint, label + value at 38% opacity |
| Error | Underline + label switch to `--md-sys-color-error` |

## Usage

```html
<md-filled-text-field label="Email"></md-filled-text-field>
<md-filled-text-field label="Email" value="hello@example.com"></md-filled-text-field>
<md-filled-text-field label="Email" disabled></md-filled-text-field>
```

## Accessibility

- The visible label is the accessible name — no separate `<label>` needed (the element handles ARIA wiring)
- For required fields, set `required` and pair with a visible asterisk or "Required" supporting text
- Errors set `aria-invalid="true"` and reference a supporting-text element via `aria-describedby`

## Do's and don'ts

| Do | Don't |
|---|---|
| Always set the `label` attribute | Use `placeholder` as the only label |
| Use `error-text` for inline validation | Hide errors behind tooltips |
| Pair with supporting text for hints (max length, format) | Cram instructions into the placeholder |
| Use `type="email"` / `tel` / `number` etc. for the right keyboard | Use `type="text"` for everything |
